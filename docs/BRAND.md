# FasalPath
**A clearer next season.**

FasalPath is the product brand for the Field Shift challenge project. “Fasal” refers to a crop; “Path” expresses a sequence of decisions, not an automatic planting prescription. The GitHub repository remains `SidhartSami/Field-Shift`.

## Identity
The original SVG mark combines field rows with a curved path and a point of observation. The crop illustrations distinguish rice, wheat, maize, chickpea, millet, mustard and mung. The aerial field scene is a schematic illustration; it is explicitly labeled and links to the actual geographic map rather than claiming to be satellite evidence.

| Colour | Hex | Purpose |
| --- | --- | --- |
| Deep pine | `#153E35` | Identity, navigation and primary text/actions |
| Harvest gold | `#D7AA52` | Field setup and selected decision accents |
| Warm ivory | `#F5F3EB` | Main workspace background |
| Irrigation teal | `#367D7A` | Effective-rain portion of the water graphic |
| Terracotta | `#B76F54` | Unmet water demand, also distinguished with hatching |

The dark theme retains the same roles with brighter text/accents. Decorative movement is avoided; comparison graphics update immediately. Navigation uses curated Lucide icons (ISC license retained at `dist/vendor/lucide/LICENSE`). The logo, field illustration and crop drawings are original SVG assets. No external image service, new account or animation library is required to display them.

## Visuals serve the decision
The water-budget comparison uses a shared scale for the current and selected rotations. It displays effective rainfall, assumed usable irrigation capped at availability, and unmet demand. Unrounded segments conserve the modelled demand; labels are rounded. Colour is supported by text, accessible SVG labels and a hatched gap. This is an annual model, not measured water use or a daily irrigation plan.

## Continuity
The original browser storage keys remain unchanged so existing fields and decisions are retained. Current exports identify the product as FasalPath. Historical snapshots keep their original identity and evidence. Existing source history and the GitHub repository's initial commit are preserved through an ordinary merge; no force push is used.
